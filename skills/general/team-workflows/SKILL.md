# Team Workflows

When someone creates or joins a team, Ổi Browser sets up a team workspace for it. Everything added
there is shared with everyone on the team, and it syncs to all of them. That makes it powerful, and
it also means it can quickly grow into an unstructured pile. A few habits keep it useful.

## Add things on purpose

- Before adding something to the team workspace, make sure the user knows it will be shared with
  the whole team.
- For anything that will keep growing, e.g. every candidate the team is hiring, agree on the
  structure first: which folders, how files are named, and what goes in each one.
- A project is a good home for a larger effort. A short skill that says how to add things to it,
  and who adds them, keeps everyone's companions adding things the same way.
- Keep personal preferences and private context out of the team workspace.

## Change shared skills carefully

- A shared skill changes how everyone's companion works, so check with the user before editing one.
- An admin who is setting things up or restructuring the workspace doesn't need to be asked every
  time. Use judgment.
- When people like to do a process slightly differently, keep the shared skill general and give
  each person a preference file in the skill's references, e.g. how one person likes their outreach
  written. Check with the user before saving a preference like this.

## Shared and private companions

A simple setup that works well: one shared team companion that everyone uses, knowing that anything
said to it is shared with the team, and a private companion for each person that stays outside the
workspace.
